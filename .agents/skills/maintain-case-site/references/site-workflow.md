# Практическое обновление существующей витрины

Читай этот файл, когда нужно изменить данные сайта, собрать выпуск или проверить
публикацию. Все пути ниже относительно workspace, если не указано иное.

## Откуда брать состояние и данные

- site/deployment.local.json: приватные адрес сайта, путь к homelab publish-скрипту,
  адресат Telegram и выбранные правила. Значений из него в публичном скилле нет.
- site/build/state.json, site/build/artifact.json и последние отчёты проверки:
  опубликованная версия, хеш архива, незавершённые действия.
- site/content/questions.edited.json: понятные формулировки вопросов. Дословные
  цитаты и их адреса сборщик берёт из принятых источников, не из редакторского текста.
- site/content/overview.edited.json: обзор, финансовая сверка, исправления,
  участники и дальнейшие запросы.
- site/content/ui.json: приватные названия, фильтры, приоритеты, исключённые
  источники и число разрешённых страниц.
- site/build/source-index.json: полный PDF, локальная страница части, л.д.,
  изображение и PDF-ссылка каждого опубликованного источника.
- output/court-package/manifest.json и исходные принятые реестры: прежняя
  подтверждённая подборка. Не перезаписывай оригиналы и замороженные результаты
  только потому, что в чате появилась другая версия.

Для каждого содержательного изменения сохрани в игнорируемых локальных данных:
причину/вход, прежнее и новое состояние, проверенные источники, затронутые карточки
и URL, результат выпуска и уведомления. Источник сообщения записывай с его ID;
личность, дата документа, дата события и дата фотографии не взаимозаменяемы.
Неподтверждённые входы держи отдельно от опубликованных фактов.

## Важные ограничения текущего сборщика

Не обходи проверки, когда новое проверенное сведение не помещается в прежний
список источников. Добавь новый источник и адресную привязку в отдельный принятый
слой и согласованно расширь входной манифест/сборку, сохраняя старые результаты.
Числа страниц и карточек являются контролем состава, а не вечным лимитом.

Проверь реализацию якорей перед вставкой и перестановкой карточек: начальная
версия назначала вопросы и обзорные якоря по позиции в массиве. Зафиксируй
существующий адрес за постоянным ID; новые элементы добавляй без перенумерации.
Если нужна миграция, сохрани старые ссылки как aliases и проверь переходы.
Одного сохранения ID в JSON недостаточно, если сборщик заново меняет slug.

Новые дословные цитаты должны проверяться по своему источнику, а не по случайному
совпадению в старой сводке. Для каждой ссылки нужен опубликованный разрешённый
источник. Не подключай целиком том ради одной страницы, если туда могут попасть
исключённые материалы. Соблюдай действующий allowlist и запрет на страницы с
секретами; техническую нечитаемость не скрывай редакторской правкой.
При исключении материала проверь фактические файлы нового dist и архива:
скрытая ссылка не удаляет прежний статический файл. Убирай лишние производные
из выпуска, сохраняя оригиналы и локальную историю.

## Сборка и проверка

Используй уже установленный runtime. Тяжёлые операции выполняй по одной.
Не переустанавливай модели и не перезапускай массовый OCR ради обновления сайта.

При изменении источников подготовь только нужные изображения/пакеты:

~~~sh
python3 site/prepare_sources.py
~~~

Команда читает текущий принятый манифест. Для новых типов источников сначала
расширь его поддержку, не подставляй непроверенный файл под прежний page ID.
Тексты и данные проверь локальной сборкой:

~~~sh
python3 site/build_site.py
~~~

Проверь затронутые карточки и поиск, дословность цитат, сохранение отрицаний,
арифметику при изменении сумм и открытие правильной исходной страницы.
Если менялась разметка или навигация, просмотри соответствующие страницы
на компьютере и телефоне. Не повторяй весь прежний аудит без причины.
Прямая ссылка должна показать нужную карточку и при переходе из того же раздела,
а не только при первом открытии сайта.

Собери архив:

~~~sh
python3 site/build_site.py --package
~~~

Архив и описание хеша сохраняются в site/build/. release.json содержит
release_id, built_at, file_count и files с path/bytes/sha256, не включая сам себя.
Проверь, что release_id отличается от опубликованного. Если изменился только
контекст сборки, не переиспользуй старый ID для другого архива: исправь генератор
версии согласованно с контрактом homelab. В архиве только обычные относительные
файлы, без symlink, приватной конфигурации, истории и credentials.

## Выпуск на homelab

Используй publish_script из site/deployment.local.json и абсолютный путь
site/build/site.tar.zst. Штатный скрипт берёт lock, передаёт архив во временное
имя, сверяет SHA-256, вызывает ограниченный deploy-wrapper, переключает релиз
с сохранением предыдущего и проверяет публичные HTTPS/redirect/anonymous 401.
Никаких GitHub/GHCR для данных дела.

Он не меняет Basic Auth, пароль, Traefik, firewall, DNAT или sudoers. Такие задачи
отдельны от обычного обновления витрины; не добавляй себе права для удобства.
Не создавай новый хостинг, чат или деплой на другом сервисе.

После успешного выпуска:

~~~sh
python3 site/verify_deployment.py
~~~

Проверка использует локальный секрет только внутри процесса, не выводит его.
Она должна подтвердить правильный release.json/index и доступ после авторизации.
Дополнительно проверь прямые URL изменённых карточек и их источников. Запиши
версию и исход выпуска в site/build/state.json и локальной истории изменений.
При сетевой неопределённости сверь удалённую версию до повторного запуска.
При блокировке или откате не отправляй сообщение «сайт обновлён».

## Telegram

Следуй TELEGRAM.md: текущие chat_id/socket берутся из приватной локальной
конфигурации/безопасного статуса. Не извлекай их из чужого CODEX_THREAD_ID.
На конкретный вход отвечай с reply_to; самостоятельная сводка допустима
для общего пакета, но не закрывает другие входящие сообщения.

Формат сводки по смыслу:

> Обновил витрину.
> • Уточнено, что именно подтверждает документ: ссылка на карточку.
> • Исправлен прежний вывод и связанные вопросы: ссылки.
> • Добавлена полная исходная страница: прямая ссылка.

Это образец, не шаблон с обязательными словами. Пиши коротко и понятным языком.
Прямой адрес включает маршрут и card/source параметр конкретной страницы;
название ссылки объясняет читателю, что он откроет. Не помещай в сводку
служебные ID, хеши и внутренние пути вместо результата.

При цитировании в группе приложи саму страницу по правилам AGENTS.md либо
сошлись на уже отправленное вложение; сайт-ссылка этого требования не отменяет.
Сводка без цитат и с прямыми ссылками на обновлённые карточки не требует
повторной пересылки всех прежних PDF.

Используй прежний request_id/payload при проверенном повторе одной отправки.
Сохрани message_id подтверждённой сводки и список опубликованных URL.
В истории могут быть сообщения с доступами: не выгружай широкую историю
в модель, для проверки доставки выбирай конкретные сообщения/метаданные.
Изменения кода и скилла коммить без case data; push в публичный remote не
следует из разрешения обновлять закрытую витрину.
